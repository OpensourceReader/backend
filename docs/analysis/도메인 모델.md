# 오픈소스 리더 도메인 모델

## 목표
- 오픈소스 리더는 오픈소스 기여의 진입 장벽을 부수는 개발자 도우미 플랫폼입니다.
- 그래서, 원하는 특정 코드에 빠르게 접근하고 쉬운 이해를 위해 아래와 같은 서비스를 제공합니다.
  - 기여 난이도가 낮고 영향이 큰 ‘핫스팟 코드’ 추천
  - 문맥 기반 코드 검색 기능
  - 코드의 사용 흐름 추적
  - 코드 관련 글 · 이슈 · PR 히스토리 연결
  - AI 기반 코드 요약 및 의도 설명

## 전체 도메인 구성
1. Analysis
2. User

### Analysis 도메인
1. 회원들은 오픈소스에 기여할 수 있는 특정 코드를 받을 수 있다.
    1. 오픈소스 코드 UI는 트리맵 형태로 제공이 된다.
2. 회원들은 프로젝트파일 트리뷰를 통해서 내부 파일들을 보고, 원하는 파일을 선택할 수 있다.
3. 회원들은 본인이 선택한 코드와 함께 이해와 기여에 도움을 줄 수 있는 자료들을 볼 수 있다. 
     1. 관련 자료 : PR/Issue + Discussion + 블로그..and more.
     2. 콜그래프(사용 흐름) : 디버깅 노고를 줄여주는 코드의 메서드들의 사용 흐름
4. 회원들이 오픈소스 내용 관련해서 검색할 수 있다.(추후 보강)
   1. 사용자가 키워드 또는 기능요구를 검색하면(ex) hibernate에서 protected 생성자가 왜 필요하니?, JPA Lazy Loading)
      - 해당 개념이 적용된 코드를 보여주고,
      - 구현 의도/배경 설명을 함께 제공한다.
   2. 코드 컨텍스트(파일 위치,관련 타입,호출 관계)를 탐색할 수 있어 “왜 여기서 이렇게 구현했는지”를 따라가는 학습 경험을 제공할 수 있어야 한다.
5. 의존성에 추가된 파일도 탐색(추후 보강)
    1. 코드의 의존성(dependency)에 추가된 라이브러리들이 레포에 있으면 추가로 보여준다.
6. 회원들이 메인페이지에서 PR/ISSUE, 블로그, 코드의 활용 정도, 레포지토리 star의 개수를 통해 전체 레포를 순위별로 볼 수 있다.
    1. 언어별, 시간별(하루,한 달,1년) 순으로 분류해서 순위를 매길 수 있다.

### 콜 그래프 (사용 흐름 정책)

콜 그래프는 **코드에 존재하는 메서드들이 실제로 어떻게 사용·연결되는지를 보여주는 사용 흐름 모델**입니다.  
본 정책의 목적은 **디버깅 및 코드 이해 과정에서 발생하는 노고를 줄이고**,  
개발자가 *“이 메서드는 왜 호출되는가, 어디로 이어지는가”* 를 빠르게 파악할 수 있도록 돕는 데 있습니다.

#### 1. 정책 결정의 기본 원칙

콜 그래프는 다음 원칙에 따라 구성됩니다.  
세부 정책에 대한 내용은 동일 폴더 내 문서를 참고합니다.

- **사실 기반 수집**
    - 바이트코드를 기준으로 실제 실행 단위 메서드를 수집합니다.
    - 소스 코드에 존재하지 않는 메서드(`<init>`, synthetic, bridge 등)도 분석 대상에 포함합니다.

- **해석과 표현의 분리**
    - 메서드 간 호출 관계의 해석(상속, 인터페이스, 외부 호출)은 정책(Strategy)으로 분리합니다.
    - 사용자에게 보여줄 범위와 형태는 표현(View) 정책을 통해 제어합니다.

- **노이즈 최소화, 정보 손실 최소화**
    - 기본 화면에서는 디버깅에 직접적인 도움이 되지 않는 요소(private 메서드, 생성자, 외부 라이브러리 호출 등)를 숨깁니다.
    - 단, 숨겨진 요소는 삭제하지 않으며, 필요 시 언제든지 다시 확인할 수 있도록 유지합니다.

- **정책 기반 가변성**
    - 사용자는 옵션(ViewOptions)을 통해 호출 흐름 정책을 변경할 수 있습니다.
    - 정책 변경 시 콜 그래프를 재수집하지 않고, 기존 분석 결과를 기반으로 표현만 재구성합니다.

### Analysis 도메인 제한사항
1. 트리맵 크기는 내부 알고리즘에 따릅니다.
2. 코드와 관련 자료의 연결도 내부 알고리즘에 따릅니다.
3. 오픈소스레포의 언어는 처음에는 자바로 진행하지만, 다음에 모든 언어로 확장합니다.

### 도메인 모델 세부
#### OpenSourceRepo
- **속성**
  - id: Long
  - cloneUrl: 레포를 클론할떄 사용한 url
- **행위**
  - addContent(): 오픈소스 레포에 컨텐츠(파일)을 추가합니다.

#### OpenSourceRepoContent
- **속성**
  - id:Long
  - path: src이후의 파일 path(추후 파일구조를 복원하는데 사용)
  - OpenSourceRepoContentName: 파일이름(/src/repo/Content.java에서 Content.java)
  - rawText: 파일의 내용
  - OpenSourceRepo: 저장한 레포
- **행위**
  - static of(): 생성

#### ContentType
- **속성**
  - value: git이 파일 구조를 저장하는 타입 이름
  - typeNumber: value의 git 식별자(8진수)

- **상수**
  - TREE: 디렉토리(/src/repo/Content.java에서 /src/repo/)
  - SOURCE_CODE: 소스파일(/src/repo/Content.java에서 Content.java)
  - OTHERS(submodule들 다른 팡들)

- **행위**
  - getContentTypeFromTypeNumber(): typeNumber에 맞는 타입을 상수로 반환 

#### OpenSourceRepoContentName
- **속성**
  - name: 파일명
- **행위**
  - private extractName(): 파일 생성 시 path에서 파일명 추출
