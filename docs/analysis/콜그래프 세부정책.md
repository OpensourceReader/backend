# 콜 그래프 세부 정책_V1

본 문서는 콜 그래프(Call Graph)를 **디버깅 및 코드 이해를 돕는 사용 흐름 분석 도구**로 활용하기 위한 세부 정책을 정의합니다.  
상위 문서의 *정책 결정의 기본 원칙*을 전제로 하며, 본 문서에서는 실제 구현 및 사용자 노출에 직접 영향을 미치는 정책을 구체화합니다.

---

## 1. 메서드 수집 정책

### 1.1 수집 기준

- 메서드 수집은 **바이트코드(.class)** 를 기준으로 수행합니다.
- JVM 실행 단위로 존재하는 모든 메서드를 분석 대상으로 포함합니다.

### 1.2 수집 대상 메서드 범위

- 사용자 정의 메서드
- 생성자(`<init>`)
- 정적 초기화 블록(`<clinit>`)
- 컴파일러 생성 메서드
    - synthetic 메서드
    - bridge 메서드

### 1.3 소스 코드 위치 정보 보강

- AST 분석을 통해 startLine, endLine 정보를 보강합니다.
- 매핑 실패 시 line 정보는 null로 두고 사유를 상태로 기록합니다.

---

## 2. 호출 관계 수집 정책

- 바이트코드 분석을 통해 호출 간선을 생성합니다.
- 호출 타입(`dispatchType`)을 함께 기록합니다.
  - dispatchType 
    - INVOKESTATIC
    - INVOKESPECIAL
    - INVOKEVIRTUAL
    - INVOKEINTERFACE
    - INVOKEDYNAMIC

---

## 3. 호출 해석(Resolution) 정책

### 3.1 외부 라이브러리 호출

- 내부에 없는 callee는 `ExternalMethodRef`로 분리 저장합니다.
- 기본 화면에서는 외부 호출을 접어서 표현합니다.

### 3.2 상속 (Virtual Dispatch)

- 저장 정책
  - invokevirtual 호출은 POLYMORPHIC 상태로 기록합니다.
  - 가능한 경우 callee 후보 목록을 함께 저장합니다.
  - 각 후보에는 다음 메타 정보를 포함합니다.
    - 상속 거리(distance)
    - 후보 선정 사유(OVERRIDE, INHERITED, DECLARED_TYPE_MATCH 등)
- 해석 규칙
  - 상속 관계에서 callee를 결정하는 규칙은 다음과 같습니다.
1. Nearest Override 우선
   - receiver 타입에서 override된 메서드가 존재하면 이를 대표 callee로 선택합니다.
2. Declared Type Chain 탐색
   - override가 존재하지 않으면 부모 타입을 따라 올라가며 구현을 탐색합니다.
3. Framework Boundary 적용
   - 상속 체인 중 외부 라이브러리 타입이 등장하면 해당 지점에서 탐색을 종료하고 외부 호출로 처리합니다.

### 3.3 인터페이스 호출

- 구현체 후보를 callee로 연결합니다.
- 폭발 시 집계 노드로 표현합니다.

### 3.4 동적 호출

- Reflection, Proxy, invokedynamic은 별도 상태로 기록합니다.

---

## 4. 필터 정책

- private, `<init>`, `<clinit>`은 저장하되 기본 화면에서는 숨깁니다.
